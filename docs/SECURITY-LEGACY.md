# امنیت و حریم خصوصی | Security & Privacy

## مدل تهدید در یک نگاه

| موضوع | وضعیت |
|---|---|
| صدا/تصویر | **P2P و رمزنگاری‌شده** (DTLS-SRTP). سرور فقط SDP/ICE را رد می‌کند و محتوا را نمی‌بیند. |
| چت، تخته، یادداشت، نظرسنجی | داخل Durable Object همان اتاق (نه دیتابیس مرکزی، نه اکانت). با خالی‌شدن اتاق پاک می‌شود. |
| فایل‌های بزرگ (زنده) | روی کانال دادهٔ WebRTC به حاضرین؛ آرشیو نمی‌شود. |
| هویت | بدون ثبت‌نام. شناسهٔ مرورگر (تصادفی، در sessionStorage) + نام انتخابی. |
| رمز اتاق | سمت سرور بررسی می‌شود؛ هش ذخیره نمی‌شود، فقط رشتهٔ کوتاه در وضعیت اتاق. |
| مسدودسازی | فهرست کوچک در همان اتاق (شناسهٔ مرورگر، **بدون ذخیره‌سازی IP**). |
| تبلیغ/ردیاب | هیچ اسکریپت ثالث، هیچ کوکی تبلیغاتی، هیچ تحلیل‌گر بیرونی. |

## ضدسوءاستفاده (و چرا رایگان می‌ماند)

* `LIMITS` در `shared/protocol.js`: سقف اندازهٔ پیام (۶۴KB)، ۴۰۰ پیام در دقیقه برای هر عضو،
  ۲۰۰ پیام تاریخچه، سقف ۱۵MB برای فایل زنده، سقف ۳۰۰KB برای تخته سفید، سقف ۲۰۰KB برای یادداشت.
* سقف نفرات هر اتاق (پیش‌فرض ۱۲، حداکثر ۱۶) و مهلت ۹۰ ثانیه‌ای پاک‌سازی اتاق خالی.
* اطلاعات TURN (کلید API) فقط در سکرت‌های Worker است و به مرورگر نمی‌رسد؛ مرورگر فقط
  اعتبار کوتاه‌عمر (۲۴ ساعت) می‌گیرد.
* مسیر `/api/ws` فقط با `Upgrade: websocket` و کد اتاق معتبر پذیرفته می‌شود.

## سرصفحه‌های امنیتی

در `public/_headers` تنظیم شده‌اند: `X-Content-Type-Options`, `X-Frame-Options: SAMEORIGIN`,
`Referrer-Policy`, `Permissions-Policy` (دوربین/میکروفن فقط self), `Strict-Transport-Security`.

## نکات برای راه‌انداز (شما)

1. اگر برای دیگران سرویس می‌دهید، عمر اتاق و گراس را متناسب تنظیم کنید (`ROOM_TTL_HOURS`, `EMPTY_GRACE_SECONDS`).
2. برای اتاق‌های حساس رمز بگذارید و «اتاق انتظار» را روشن کنید.
3. TURN را فقط از سکرتها بدهید (`wrangler secret put`), هرگز داخل `wrangler.toml`.
4. کلید/توکن‌ها را در GitHub Secrets نگه دارید (همان کاری که دکمهٔ Deploy می‌کند).

## گزارش آسیب‌پذیری

لطفاً به‌جای Issue عمومی، یک Issue با برچسب `security` بزنید بدون جزئیات اجرایی،
یا از طریق بخش Security → Report a vulnerability در گیت‌هاب اطلاع دهید. پاسخ در حد توان سریع خواهد بود.
