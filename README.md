## ✨ چه چیزی می‌گیرید؟

یک اتاق تصویری/صوتی کامل با **۱۲۴ قابلیت واقعی و پیاده‌سازی‌شده** — از جمله:

| 🧩 | قابلیت |
|---|---|
| 🎥 | تماس تصویری گروهی (تا ۱۲ نفر) + حالت **فقط صدا** برای اینترنت ضعیف |
| 💬 | چت لحظه‌ای + پاسخ، ویرایش، حذف، سنجاق، واکنش، جست‌وجو، خروجی JSON |
| 📎 | ارسال **فایل، عکس و ویس** — فشرده‌سازی خودکار عکس، انتقال قطعه‌ای تا ۱۵ مگابایت |
| 🎨 | **تخته سفید مشترک** (قلم/خط/مستطیل/دایره/فلش/متن، واگرد، ذخیرهٔ PNG) |
| 🖥️ | **اشتراک صفحه** (تب/پنجره/تمام‌صفحه + صدای سیستم) با سه سطح کیفیت |
| 🧰 | نظرسنجی زنده، یادداشت مشترک، پیام به آینده، زیرنویس خودکار فارسی، ترجمه، ضبط جلسه، پومودورو، کوییز، اتاق‌های موازی، بیدارباش (Wake Lock)، تصویر در تصویر |
| 👑 | میزبانی: انتقال میزبانی، اخراج/مسدودسازی، بستن میکروفن همه، قفل اتاق، **اتاق انتظار**، تغییر عمر اتاق، پایان برای همه |
| 🇮🇷 | بهینه‌سازی ایران: کل صفحه **زیر ۵۰KB** (فقط ۱ درخواست JS)، بدون فونت/آیکون بیرونی، تشخیص خودکار کیفیت، کاهش خودکار روی شبکهٔ بد |
| 🧊 | **اتاق با WebSocket Hibernation** — اتاق خواب می‌رود و هزینه‌ای مصرف نمی‌کند، ولی عضوها می‌مانند (مناسب پلن رایگان و جلسهٔ ۸ ساعته) |
| 💾 | اتاق تا وقتی **حداقل یک نفر** داخلش باشد حذف نمی‌شود (تا سقف عمر انتخابی، پیش‌فرض ۸ ساعت، حداکثر ۲۴ ساعت) — و وقتی همه رفتند، چت/تخته/یادداشت کاملاً پاک می‌شود |

فهرست کامل ۱۲۴ قابلیت با جست‌وجو: صفحهٔ اصلی سایت → بخش «۱۲۴ قابلیت»، و داخل اتاق → دکمهٔ ❓

## 🚀 سه راه برای بالا آوردن (همه رایگان)

### ۱) یک‌کلیکی (کمترین زحمت)
روی دکمهٔ **Deploy to Cloudflare** بزنید → وارد گیت‌هاب شوید → کلودفلر خودش مخزن را فورک می‌کند،
پروژه را می‌سازد و منتشر می‌کند → در پایان یک آدرس `https://hamkalam.<username>.workers.dev` می‌گیرید.

### ۲) با دستور (پیشنهادی برای توسعه)
```bash
git clone https://github.com/amingangmanatgh2-hash/gaming-hub hamkalam
cd hamkalam
npm install
npx wrangler login      # یک‌بار
npm run deploy          # ساخت + انتشار روی Workers
```
خروجی: یک آدرس `workers.dev` که هم سایت است و هم سرور سیگنالینگ.

### ۳) Cloudflare Pages
```
داشبورد → Workers & Pages → Create → Pages → Connect to Git → مخزن را انتخاب کنید
Build command:     npm run build
Build output dir:  public
```
سپس در **Settings → Functions → Durable Object bindings**:
`Variable name: ROOMS` و `Class name: Room` (و Apply).
(Durable Object باید در `wrangler.toml` هم تعریف شده باشد — همین حالا هست.)

> ⚠️ نکته: اگر بخش Durable Objects را بایند نکنید، سایت بالا می‌آید ولی
> **چت/سیگنالینگ کار نمی‌کند** (صفحهٔ ورود چنین پیامی می‌دهد). این حالت فقط برای دموی ظاهر مفید است.

## 💸 هزینهٔ واقعی: چقدر رایگان است؟

| سرویس | سهمیهٔ رایگان | معادل در این اپ |
|---|---|---|
| Workers | ۱۰۰٫۰۰۰ درخواست/روز | هر بار بازکردن صفحه یا `/api/room` یک درخواست |
| Durable Objects | با **hibernation** تقریباً مصرف نشدن CPU هنگام سکوت | هر اتاق یک DO؛ اتاق بی‌حرکت = هزینهٔ صفر |
| WebSocket | پیام‌های سوکت در حالت hibernation ارزان‌اند | چت و سیگنالینگ |
| **صدا/تصویر** | ❌ از سرور عبور نمی‌کند | P2P مستقیم بین مرورگرها (مصرف کلودفلر: صفر) |
| TURN رایگان کلودفلر | **۱ ترابایت در ماه** | فقط برای کاربران پشت NAT سخت (اینترنت موبایل) |

پس: چند ده اتاق ۸ ساعته در روز، عملاً در پلن رایگان جا می‌شود. پهنای‌باند صدا/ویدیو هم
روی دوش کلودفلر نیست (مگر وقتی TURN لازم شود).

## 🛰️ اتصال صدا/تصویر روی اینترنت ایران

پیش‌فرض اپ **فقط STUN** است: صدا و تصویر مستقیم بین مرورگرها می‌رود ⇒ کم‌تأخیرترین و
کم‌مصرف‌ترین حالت. این بیشتر مواقع کار می‌کند، ولی بعضی اپراتورهای موبایل **CGNAT** دارند
و اتصال مستقیم ممکن نمی‌شود. راه‌حل رایگان و داخل کلودفلر:

1. داشبورد کلودفلر → **Realtime → TURN Server → Create TURN key**
2. دو مقدار را ست کنید:
   ```bash
   npx wrangler secret put TURN_KEY_ID
   npx wrangler secret put TURN_KEY_API_TOKEN
   npx wrangler deploy
   ```
3. تمام. اپ خودش برای هر کاربر اعتبار کوتاه‌عمر TURN می‌گیرد (سرور کلید را به مرورگر نمی‌دهد).

دکمهٔ «🌐 تأخیر» در صفحهٔ اصلی، نزدیک‌ترین لبهٔ کلودفلر و پروفایل پیشنهادی کیفیت را نشان می‌دهد.

## 🧠 معماری (چرا این‌قدر سبک است؟)

```
مرورگر A ──┐                            ┌── WebRTC (صدا/تصویر/فایل زنده)
            ├── WebSocket ──► Durable Object «اتاق» ◄──┤
مرورگر B ──┘   (JSON سبک)      (hibernation + SQLite) └── WebRTC
```

* **استیج و منطق اتاق**: سیگنالینگ + چت + تخته + نظرسنجی + اعضا، همه در یک `Durable Object` به‌ازای هر اتاق.
* **WebRTC Mesh**: هر شرکت‌کننده دو m–line از پیش آماده (صدا + تصویر) می‌سازد تا روشن/خاموش‌کردن
  میکروفن و دوربین **هیچ مذاکرهٔ مجددی** نخواهد ⇒ کاملاً روان روی اینترنت ضعیف.
* **مذاکرهٔ مودبانه** (Perfect Negotiation) + راه‌اندازی مجدد ICE ⇒ تحمل قطعی‌های شبکه.
* **دو بک‌اند با یک کد**: `worker/` (Workers + Durable Objects) و `functions/` (Pages Functions) هر دو از
  `shared/api.js` استفاده می‌کنند ⇒ رفتار یکسان.
* **بستهٔ فرانت**: esbuild؛ کل اپ (بدون بستهٔ سنگین) زیر ۵۰KB، به‌صورت gzip زیر ۲۵KB برای صفحهٔ اصلی.

### ساختار پوشه‌ها
```
shared/      پروتکل، ICE/TURN، API مشترک (یک کد برای Workers و Pages)
worker/      ورودی Workers + کلاس Room (Durable Object)
functions/   معادل Pages Functions
src/core/    socket, rtc(mesh), media, files, net, util
src/features/registry.js   فهرست ۱۲۴ قابلیت (یک‌جا برای سایت، راهنما و جست‌وجو)
src/ui/      home.js و room.js (باندل‌شدهٔ اتاق: chat, board, tools)
public/      HTML/CSS/آیکون/manifest/SW/404/_headers/_redirects
scripts/     build.mjs (esbuild) و dev-server.mjs (سرور توسعهٔ محلی)
tests/       آزمون پروتکل، DOM (jsdom) و سرتاسری سیگنالینگ (WebSocket)
```

## 🧪 توسعهٔ محلی

```bash
npm install
npm run dev        # سرور محلی روی http://localhost:8788 (بدون اکانت، با سیگنالینگ نمونه)
npm run dev:worker # اجرای واقعی workerd + Durable Objects (نسخهٔ کلودفلر، کاملاً لوکال)
npm test           # ۱۴ آزمون: پروتکل، بار آمدن صفحه‌ها، و e2e سیگنالینگ
npm run build      # باندل نهایی
```

> `npm run dev` (پورت ۸۷۸۸) کاملاً آفلاین کار می‌کند (سرور سیگنالینگ Node با همان پروتکل DO).
> `npm run dev:worker` (پورت ۸۷۸۷) همان چیزی است که روی کلودفلر اجرا می‌شود، پس معتبرترین آزمایش است.

## 🔒 حریم خصوصی

* صدا/تصویر **مستقیم بین مرورگرها** می‌رود؛ سرور ما فقط JSON سبک سیگنالینگ را رد می‌کند.
* چت/تخته/یادداشت داخل همان اتاق (Durable Object) ذخیره می‌شود و با خالی‌شدن اتاق **کامل پاک** می‌شود.
* فایل‌های بزرگ فقط به‌صورت زنده برای حاضرین پخش می‌شوند و آرشیو نمی‌شوند.
* بدون هیچ اسکریپت ثالث، بدون تبلیغ، بدون ردیاب. رمز اتاق سمت سرور بررسی می‌شود.

## ❓ پرسش‌های پرتکرار

**چند نفر؟** پیش‌فرض ۱۲ (قابل تنظیم تا ۱۶). برای کلاس بزرگ‌تر، چند اتاق یا «اتاق‌های موازی» (`CODE-1`…`CODE-5`).
**روی موبایلِ ضعیف؟** در صفحهٔ ورود پروفایل «سبک» یا «فقط صدا» را بزنید؛ اپ هم خودش پیشنهاد می‌دهد.
**اتاق چه زمانی پاک می‌شود؟** با خالی‌شدن اتاق پس از ~۹۰ ثانیه (قابل تغییر با `EMPTY_GRACE_SECONDS`)، یا پایان عمر اتاق.
**چه‌قدر دوام می‌آورد؟** عمر پیش‌فرض هر اتاق ۸ ساعت است و میزبان می‌تواند وسط جلسه تا ۲۴ ساعت تمدید کند.
**می‌شود روی دامنهٔ خودم؟** بله؛ در تنظیمات Worker/Pages گزینهٔ Custom Domain را بزنید (اکانت کلودفلر + دامنه کافی است).
**چرا دوربین من داخل پیش‌نمایش باز نمی‌شود؟** آی‌فریم‌ها اجازهٔ دوربین ندارند؛ صفحه را در تب جدید باز کنید (اپ خودش راهنمایی می‌کند).

## 🐛 عیب‌یابی سریع

| نشانه | راه‌حل |
|---|---|
| «سیگنالینگ فعال نیست» | روی Pages بایند `ROOMS ← Room` را اضافه کنید، یا همان روش Workers را استفاده کنید |
| همه به هم وصل نمی‌شوند | کلیدهای TURN را ست کنید (بخش بالا) |
| صدای خودم را می‌شنوم | هدفون بزنید یا نویزکشی/حذف اکو را در تنظیمات روشن بگذارید |
| اتاق پیدا نمی‌شود | کد اشتباه است یا عمر اتاق تمام شده — اتاق تازه بسازید |
| در Cloudflare: `Could not detect a directory containing static files` | مخزن/شاخه‌ای که Cloudflare می‌سازد **خالی** است (مثلاً قبل از انتقال کد ساخته شده). مطمئن شوید کد روی شاخهٔ پیش‌فرض مخزن مبدأ هست، بعد دوباره دکمهٔ Deploy را بزنید یا در Build History → **Retry build** |
| صفحه روی اینترنت ضعیف سنگین است | در تنظیمات، «حالت داده‌کم» را روشن و کیفیت را «سبک/فقط صدا» کنید |
