## ۱) قابلیت‌ها — وضعیت تأییدشده

| قابلیت | وضعیت | توضیح |
|---|---|---|
| رابط کاربری مدرن تیره + RTL/LTR | ✅ کامل و تست‌شده | فارسی پیش‌فرض، انگلیسی کامل، واکنش‌گرا (موبایل/تبلت/دسکتاپ)، کاهش حرکت (reduced-motion) |
| PWA قابل نصب | ✅ | مانیفست + Service Worker + حالت آفلاین |
| جادوگر راه‌اندازی اولیه | ✅ تست‌شده | ساخت مدیر با گذرواژه قوی، قفل دائمی پس از تکمیل (تست ۴۱۰) |
| ثبت‌نام/ورود ایمیلی | ✅ تست‌شده | PBKDF2 با ۳۱۰هزار تکرار (جایگزین پشتیبانی‌شده Argon2id در Workers)، قفل‌کنی پس از تلاش ناموفق |
| ورود با گوگل (OIDC واقعی) | ⚙️ نیازمند کلید | کد کامل و آماده؛ بدون Client ID/Secret واقعی دکمِه پیام راهنما نشان می‌دهد (هیچ شبیه‌سازی نیست) |
| تأیید ایمیل/بازیابی گذرواژه | ✅ با کد ۶ رقمی | ارسال ایمیل نیازمند کلید Resend است؛ در نبود آن «حالت توسعه» کد را نشان می‌دهد |
| چت با مدل‌های OpenAI-Compatible | ✅ تست‌شده | هر ارائه‌دهنده سازگار (OpenAI، OpenRouter، LiteLLM…)؛ **بدون پیکربندی، پیام راهنما نشان داده می‌شود — پاسخ ساختگی نیست** |
| سهمیه روزانه پیام/ویدیو | ✅ تست‌شده | Durable Object اتمیک + آینه D1؛ تست همزمانی ۵ درخواست ⇒ فقط ۱ رزرو |
| استودیو ویدیو | ✅ تست‌شده | صف/وضعیت/پیشرفت/تاریخچه/دانلود؛ رهاسازی سهمیه در شکست (یک‌بار، تست‌شده) |
| اشتراک‌ها (FREE/PLUS/PRO) | ✅ | کاملاً قابل ویرایش از پنل مدیریت؛ اعمال entitlement در بک‌اند |
| پرداخت زرین‌پال | ✅ با Stub واقعی تست‌شده | Request/Verify رسمی REST v4، ضدتکرار ref_id، idempotency، فعال‌سازی فقط پس از تأیید authoritative |
| کارت‌به‌کارت دستی | ✅ تست‌شده | هرگز خودکار فعال نمی‌شود؛ تأیید مدیر + لاگ حسابرسی |
| پنل مدیریت | ✅ | کاربران، طرح‌ها، ارائه‌دهندگان، پرداخت، تراکنش‌ها، بررسی رسید، کشورها، قابلیت‌ها، حالت تعمیرات، audit |
| RBAC سمت سرور | ✅ تست‌شده | ۴۰۱/۴۰۳ واقعی برای همه مسیرهای `/api/admin/*` |
| CSRF/نشست امن | ✅ تست‌شده | کوکی HttpOnly+Secure+SameSite، هدر ضد CSRF، reauth برای عملیات حساس |

> اصل طلایی پروژه: **هیچ قابلیتی فقط با «ظاهر» ادعا نمی‌شود.** هر جا به اعتبار بیرونی نیاز باشد (کلید گوگل، مرچنت زرین‌پال، کلید ارائه‌دهنده AI)، بدون آن اعتبار پیام راهنمای شفاف نمایش داده می‌شود.

## ۲) معماری

```
┌────────────────────────────────────────────────────────────┐
│ Cloudflare Worker (یک سرویس واحد)                            │
│  ├─ Assets: فرانت‌اند React+Vite (SPA فارسی‌اول، RTL)        │
│  ├─ API:    Hono — /api/*                                   │
│  ├─ D1 (SQLite): کاربران، نشست‌ها، طرح‌ها، تراکنش‌ها، لاگ   │
│  ├─ R2: آپلودها و فایل‌های خروجی                            │
│  ├─ Durable Objects:                                        │
│  │   ├─ QuotaCoordinator → رزرو اتمیک سهمیه روزانه          │
│  │   └─ RateLimiter      → محدودسازی آنیIP/اکانت           │
│  └─ Secrets: کلیدها (wrangler secret)                       │
└────────────────────────────────────────────────────────────┘
```

- **چرا Durable Object برای سهمیه؟** چون `reserve` باید اتمیک باشد؛ تست ۵ درخواست همزمان با سقف ۱ → دقیقاً ۱ موفق، ۴ رد (۴۲۹).
- **وضعیت طولانی ویدیو:** رکورد D1 + Polling وضعیت از ارائه‌دهنده؛ مقیاس‌پذیر و سازگار با محدودیت زمان اجرای Workers.

## ۳) اجرای محلی (توسعه)

پیش‌نیاز: Node.js 20+ و npm.

```bash
npm install
cp .dev.vars.example .dev.vars   # مقادیر توسعه (غیرواقعی)
npm run dev                      # بیلد + مایگریشن محلی + wrangler dev روی پورت 8787
```

برای تست سرتاسری چت/ویدیو/پرداخت بدون سرویس واقعی، سرور «موک» را اجرا کنید:

```bash
node scripts/mock-providers.mjs   # OpenAI/ویدیو/زرین‌پال ساختگی روی :9999
node scripts/seed-demo.mjs        # ساخت دیتای نمایشی (مدیر/کاربر/پیکربندی)
node scripts/smoke.mjs            # اجرای ۶۳ تست سرتاسری
npm test                          # تست‌های واحد (vitest)
```

حساب‌های دمو (فقط محلی): `admin@amin.demo / Admin#Demo1403` و `user@amin.demo / User#Demo1403`.

## ۴) استقرار واقعی روی Cloudflare

قدم‌به‌قدم (به‌فارسی؛ لازم نیست چیز اضافه‌ای نصب کنید):

```bash
# ۱) ورود به حساب Cloudflare
npx wrangler login

# ۲) ساخت دیتابیس D1 → خروجی database_id را در wrangler.toml جای REPLACE_WITH_YOUR_D1_DATABASE_ID بگذارید
npx wrangler d1 create amin-ai-ultra

# ۳) اعمال مایگریشن‌ها روی دیتابیس واقعی
npx wrangler d1 migrations apply amin-ai-ultra --remote

# ۴) ساخت سطل R2
npx wrangler r2 bucket create amin-ai-ultra-assets

# ۵) ست‌کردن رمز مخفی اپلیکیشن (اجباری) — یک رشته تصادفی ۴۸ کاراکتری
openssl rand -hex 32
npx wrangler secret put APP_SECRET       # مقدار خروجی مرحله قبل را پیست کنید

# ۶) (اختیاری) گوگل و ایمیل — توضیحات در بخش‌های ۸ و ۹
npx wrangler secret put GOOGLE_CLIENT_ID
npx wrangler secret put GOOGLE_CLIENT_SECRET
npx wrangler secret put EMAIL_API_KEY

# ۷) دیپلوی
npm run deploy
```

خروجی `wrangler deploy` یک آدرس `https://amin-ai-ultra.<your-subdomain>.workers.dev` می‌دهد — **همان لینک عمومی پروژه شماست.**

### چک‌لیست قبل از بالا رفتن
- [ ] `database_id` واقعی در `wrangler.toml`
- [ ] `APP_SECRET` قوی (غیرپیش‌فرض)
- [ ] کلید ارائه‌دهنده AI از پنل مدیریت یا secret (بخش ۶)
- [ ] مرچنت زرین‌پال معتبر (بخش ۷)
- [ ] Redirect URI گوگل دقیقاً برابر `https://<دامنه‌شما>/api/auth/google/callback`

## ۵) راه‌اندازی اولیه (جادوگر)

۱. اولین بازدید از سایت → هدایت خودکار به `/setup` (رابط کاملاً فارسی و RTL).
۲. ساخت **حساب مدیر** با گذرواژه قوی (حداقل ۱۰ نویسه + حرف + عدد). رمز با PBKDF2/310k هش می‌شود.
۳. انتخاب نام سایت و زبان پیش‌فرض → «تکمیل راه‌اندازی».
۴. انتقال خودکار به `/admin`. **صفحه راه‌اندازی پس از آن برای همیشه قفل می‌شود (۴۱۰)** و ادعای مجدد حساب مدیر ممکن نیست.
۵. گذرواژه پیش‌فرض در کد وجود ندارد؛ بازیابی گذرواژه مدیر از مسیر «فراموشی گذرواژه» (ایمیل) انجام می‌شود.

> اعتبارسنجی ادعای اولیه: درخواست‌های `/api/setup` ریت‌لیمیت می‌شوند (۱۰ بار در ساعت برای هر IP) و چرخه ادعا اتمیک است؛ فقط اولین درخواست موفق فلگ را می‌چرخاند.

## ۶) پیکربندی ارائه‌دهندگان هوش مصنوعی

از **مدیریت ← ارائه‌دهندگان و مدل‌ها**:

### چت (OpenAI-Compatible)
- نوع: `چت (سازگار با OpenAI)`
- Base URL مثال‌ها: `https://api.openai.com/v1` ، `https://openrouter.ai/api/v1` ، LiteLLM خودمیزبان شما
- کلید API: در پایگاه‌داده فقط سمت سرور نگه داشته می‌شود و **هیچ‌وقت در پاسخ API بازنمی‌گردد** (تست‌شده).
- سپس از «مدل جدید»: `model_key` مثل `gpt-4o-mini`، سطح (`basic/plus/pro`).

> بهترین‌پractice برای کلید اصلی: به‌جای ثبت در DB می‌توانید Provider را با `base_url` متناظر استفاده‌کننده از secret خود میزبانی کنید (مثل پراکسی LiteLLM). در هر صورت کلید هرگز لو نمی‌رود.

### ویدیو (HTTP عمومی)
قرارداد موردانتظار (در UI هم آمده):
- `POST {base}/jobs` با بدنه `{prompt, aspect_ratio, duration_seconds, model}` ← `{job_id, status}`
- `GET {base}/jobs/{id}` ← `{status, progress, result_url, error}`
- `status ∈ queued|running|succeeded|failed`

بسیاری از APIهای async ویدیو (Runware، PiAPI، سرویس‌های خودمیزبان ComfyUI...) با این قرارداد یا آداپتور کوچک سازگارند. **بدون ارائه‌دهنده معتبر، استودیو پیام راهنمای شفاف می‌دهد و هیچ ویدیوی ساختگی تولید نمی‌شود.**

> ⚠️ Cloudflare به‌خودی‌خود GPU استنتاج یا تولید ویدیوی نامحدود ارائه نمی‌دهد؛ هزینه و ظرفیت تابع ارائه‌دهنده بیرونی شماست که قانوناً باید برای کشور/کسب‌وکار شما مجاز باشد. ما هیچ محدودیت منطقه‌ای ارائه‌دهنده را دور نمی‌زنیم.

دکمه **«تست اتصال»** وضعیت دسترسی یا کلید را گزارش می‌دهد.

## ۷) پیکربندی پرداخت

### زرین‌پال (REST v4 واقعی)
۱. یک **مرچنت معتبر** زرین‌پال بگیرید (واجد شرایط بودن فعلی کسب‌وکار شما را از خود زرین‌پال بررسی کنید؛ ما به‌صورت خودکار هیچ endpoint یا credential ساخته‌ای نمی‌سازیم).
۲. مدیریت ← پرداخت:
   - درگاه: `zarinpal`
   - Merchant ID: شناسه ۳۶رقمی
   - Sandbox: برای تست
   - Base URL پیش‌فرض: `https://api.zarinpal.com/pg/v4`
   - مسیر موفقیت/ناموفقیت: پیش‌فرض `/pay/result?status=ok` و `...failed`
۳. ذخیره نیازمند **ورود مجدد گذرواژه مدیر** است (reauth یک‌بارمصرف — تست‌شده).
۴. Callback عمومی `GET /api/payments/zarinpal/callback` مبلغ‌مانعه را از **رکورد خودمان** می‌خواند (نه کوئری)، سپس `verify.json` صدا می‌زند؛ فقط `code=100` یا `101` فعال‌سازی می‌کند، `ref_id` یکتا است و replay مسدود می‌شود (تست‌شده). فعال‌سازی اشتراک دقیقاً یک‌بار اتفاق می‌افتد (CAS روی `status='pending'`).
۵. اثر جانبی ثبت‌شده: پرداخت موفق IRR ⇒ «کشور تأییدشده» کاربر `IR` می‌شود (بخش ۱۰).

### کارت‌به‌کارت (دستی)
- اطلاعات کارت توسط مدیر ثبت می‌شود و به کاربر نمایش داده می‌شود.
- کاربر «رسید» ثبت می‌کند → تراکنش **pending** می‌ماند؛ **هیچ اسکرین‌شات یا ادعایی خودکار فعال‌سازی نمی‌کند.**
- مدیر در «بررسی کارت‌به‌کارت» تأیید/رد می‌کند (+یادداشت، +audit log). تأیید ⇒ فعال‌سازی اشتراک.
- **ما هرگز رمز بانک، OTP یا CVV نمی‌پrسیم و صفحه بانکی جعلی نمی‌سازیم.** پرداخت آنلاین همیشه با انتقال به میزبان درگاه رسمی انجام می‌شود.

## ۸) ورود با گوگل (OAuth)

۱. در [Google Cloud Console](https://console.cloud.google.com/) یک OAuth Client (Web) بسازید.
۲. Authorized redirect URI: `https://<دامنه‌شما>/api/auth/google/callback`
۳. ست کنید:
```bash
npx wrangler secret put GOOGLE_CLIENT_ID
npx wrangler secret put GOOGLE_CLIENT_SECRET
```
۴. جریان: `start` (state امضاشده HMAC) → Google → `callback` (تعویض code + اعتبارسنجی id_token و aud) → اتصال/ساخت حساب → نشست امن.

> این سرویس ممکن است در همه کشورها/شبکه‌ها در دسترس نباشد؛ به‌همین‌دلیل **ثبت‌نام ایمیلی همیشه به‌عنوان مسیر جایگزین باز است** و ما هیچ تضمینی برای کارکرد سرویس‌های ثالث در هر کشوری نمی‌دهیم.

## ۹) ایمیل و تأیید ایمیل

- فرستنده HTTP سازگار با Resend: `EMAIL_API_KEY` و `EMAIL_FROM`.
- بدون کلید: «حالت توسعه» — کد ۶رقمی فقط در پاسخ API (و به‌صورت toast) نمایش داده می‌شود تا جریان تأیید/بازیابی قابل تست باشد. با `auth_policy.allow_dev_code_echo=false` و ست‌کردن کلید واقعی، خاموش می‌شود.
- ضد brute-force: کدها ۱۰ دقیقه‌ای، ۵ تلاش، یک‌بارمصرف و HMAC-هش‌شده‌اند. ریت‌لیمیت درخواست کد داریم.

## ۱۰) سیاست سهمیه ویدیو و تعیین کشور (مهم)

- **اصول:** سقف هر کاربر از «طرح فعال» + «کشور تأییدشده» او (سمت سرور) خوانده می‌شود. **انتخاب دستی کشور در کلاینت اثبات محسوب نمی‌شود** و فقط برای قالب‌بندی نمایش است.
- منابع تأیید کشور: (الف) پرداخت تسویه‌شده IRR از درگاه (خودکار)، (ب) تأیید دستی مدیر — هر دو با منبع در DB ثبت و در audit مستند می‌شوند.
- سیاست اولیه طرح رایگان (کاملاً قابل‌ویرایش از پنل): کاربران تأییدشده ایران **۲ ویدیو موفق در روز**؛ سایر کاربران تأییدشده **۱ ویدیو موفق در روز**.
- «روز» بر اساس منطقه‌زمانی پیکربندی‌شده (`quota_policy.day_timezone` پیش‌فرض `Asia/Tehran`) محاسبه می‌شود.
- ضد دورزدن: رزرو اتمیک DO + شمارش روی حساب **تأییدشده** (نه درخواست) + سقف مکالمه/آپلود/ریت‌لیمیت IP + فعال‌سازی فقط از کانال‌های authoritative + شمارش فقط «موفق» طبق سیاست (`video_count_only_successful`) — رزرو شکست‌خورده‌ها آزاد می‌شود (یک‌بار، اتمیک، تست‌شده).
- هر کشور می‌تواند قابلیت‌ها را محدود کند (مدیریت ← برند/کشورها) و پیام منطقه‌ای شفاف به کاربر نمایش داده می‌شود.

## ۱۱) امنیت

- هش گذرواژه: PBKDF2-HMAC-SHA256 با ۳۱۰٬۰۰۰ تکرار + نمک ۱۶بایتی (در محیط Worker جایگزین پشتیبانی‌شده Argon2id است؛ base modern چون WebCrypto بومی و بدون وابستگی wasm است). مهاجرت آینده به Argon2id ساده است (فرمت هش نسخه‌بندی شده است).
- نشست‌ها: توکن تصادفی ۳۲بایتی؛ در DB فقط **SHA-256 هش توکن** نگهداری می‌شود؛ کوکی `HttpOnly; Secure; SameSite=Lax; Path=/`؛ خروج/تعلیق ↔ ابطال فوری.
- CSRF: هدر `X-Requested-With` برای همه متدهای غیر GET + بررسی Origin هم‌میزبان + SameSite.
- ریت‌لیمیت: DO برای login/ثبت‌نام/کدها/checkout/کل API.
- reauth یک‌بارمصرف برای: تغییر نقش، تنظیمات پرداخت، حذف حساب (به‌همراه تأیید متنی DELETE).
- عدم‌افشا: کلید API ارائه‌دهنده، باززین‌پال merchant_id (mask در پاسخ)، رمزها، توکن‌ها، هش‌ها — هرگز در پاسخ بازنمی‌گردند (تست‌شده: `api_key` در لیست ادمین و کانفیگ عمومی نیست).
- audit log: رویدادهای امنیتی/مدیریتی با redaction خودکار کلیدهای حساس؛ بدون ثبت رمز.
- Headers: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`.

## ۱۳) محدودیت‌ها و کارهای باقی‌مانده

1. **ورود گوگل** تا وقتی Client ID/Secret واقعی ست نشود پیام «پیکربندی نشده» می‌دهد (عمدی — شبیه‌سازی نمی‌کنیم).
2. **پرداخت واقعی** تا مرچنت معتبر زرین‌پال ست نشود غیرفعال است؛ جریان کامل با Stub رسمی-سطح تست شده است. قبل از استفاده واقعی، واجد شرایط بودن مرچنت و مستندات فعلی را از زرین‌پال تأیید کنید.
3. **ارائه‌دهندگان AI/ویدیو** باید از پنل ادمین افزوده شوند؛ بدون آن‌ها پیام راهنما نمایش داده می‌شود. سازگاری قرارداد ویدیو در بخش ۶.
4. **ارسال ایمیل** نیازمند کلید Resend است؛ در غیر این‌صورت «حالت توسعه» فعال است.
5. **تاریخچه/دانلود ویدیو:** `result_url` مستقیم ارائه‌دهنده است؛ در صورت نیاز می‌توان لایه R2 sign-url افزود (الان فایل‌های آپلودی کاربر از همان الگو استفاده می‌کنند).
6. Cron/Scheduled reconciliation (تمیزکاری نشست‌های منقضی، تطبیق تراکنش‌های معلق قدیمی) به‌صورت کامنت در بخش بعدی آمده است — در نسخه‌های بعدی قابل روشن‌کردن.
